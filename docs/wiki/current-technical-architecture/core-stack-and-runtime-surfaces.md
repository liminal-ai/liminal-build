# Core Stack and Runtime Surfaces

Liminal Build runs on a single TypeScript stack composed across four runtime surfaces: the browser client, the Fastify control plane, the sandbox runtime, and the durable stores. Fastify owns orchestration, auth, source hydration, and integration boundaries; Convex holds durable platform state behind the control plane; GitHub holds canonical code truth; and the sandbox runtime owns disposable working filesystems hydrated from those canonical sources. The canonical-source split — Convex for artifacts and platform state, GitHub for code, and the sandbox for working state only — is the anchor every other choice falls out of.

## Runtime Surfaces

The four surfaces below partition where code runs and what each surface owns. Tool Runtime is not its own surface; it executes inside the Sandbox Runtime alongside the in-environment script executor.

### Browser Client

The browser client is the Vite-built TypeScript app under `apps/platform/client/`. Fastify serves the bundled client in production and wraps the Vite dev server as middleware in development, so every request passes through the same Fastify origin. The client renders the project shell, process work surface, and review workspace from typed snapshots and upserts, never raw provider deltas.

| Property | Value |
|-|-|
| Hosted by | Fastify (production) / Vite middleware (dev) |
| Owns | feature surfaces under `client/features/`, `client/app/` bootstrap and store, `client/browser-api/` |
| Speaks | HTTP REST and WebSocket upserts over the same Fastify origin |
| Receives | typed snapshot and upsert messages, never raw provider deltas |

### Fastify Control Plane

The Fastify control plane under `apps/platform/server/` owns auth mediation, process orchestration, source hydration, environment lifecycle, and every integration boundary. It is the only surface that holds Convex, GitHub, WorkOS, or Daytona credentials, and it mediates every cross-surface call.

| Property | Value |
|-|-|
| Owns | routes, route handlers, services, plugins, error catalog, integration boundaries (Convex, GitHub, sandbox providers) |
| Speaks to client | HTTP REST + WebSocket |
| Speaks to durable | Convex queries/mutations + Octokit calls |
| Speaks to sandbox | one-shot script execution + `ExecutionResult` reception |
| Mediates | every cross-surface communication; no surface bypasses Fastify |

### Sandbox Runtime

The [sandbox runtime](../conventions/glossary.md) is the disposable working filesystem attached to a process, hydrated from canonical sources and executed against by one-shot TypeScript module scripts. The control plane sends a script payload, the in-environment executor runs it against a process-scoped tool API, and a structured `ExecutionResult` returns to the control plane. The sandbox is never canonical truth and is always reconstructible.

| Property | Value |
|-|-|
| Provider implementations | Local (in-process), Daytona (cloud) |
| Owns | working filesystem, in-environment script execution, structured result emission |
| Hydrates from | Convex artifact versions and GitHub-backed repositories through provider-mediated materialization |
| Returns | `ExecutionResult` covering history, outputs, side-work, artifact and code checkpoint candidates, source usage, archive entries |
| Truth status | working state only; never canonical truth and always reconstructible |

### Durable Stores

The durable stores carry truth that survives sandbox loss. Convex owns every durable platform table under `convex/` — projects, processes, artifacts and versions, package snapshots, sources, archive entries and derived views. GitHub owns canonical code state for every writable source attachment, and the browser never reads or writes either store directly.

| Property | Value |
|-|-|
| Convex owns | every durable platform table (projects, processes, artifacts, packages, sources, archive, …) |
| GitHub owns | canonical code state for all writable source attachments |
| Sandbox role | hydration source and checkpoint target; never canonical |
| Browser access | none direct; all reads and writes pass through Fastify |

## Cross-Surface Communication

Six transports carry every cross-surface call. The control plane sits between the browser and every other surface.

| Transport | Endpoints | Direction | Notes |
|-|-|-|-|
| HTTP REST | `apps/platform/server/routes/` | browser ↔ Fastify | the only request path the browser uses for state-changing work; CSRF-protected on mutations |
| WebSocket Upserts | `/ws/projects/{projectId}/processes/{processId}` | Fastify → browser | snapshot then upserts; never raw provider deltas |
| Convex Client | `convex/_generated/api` | Fastify ↔ Convex | the platform talks to Convex with trusted credentials; clients never see Convex directly |
| Octokit | `@octokit/rest` calls into `api.github.com` | Fastify ↔ GitHub | source hydration and code checkpoint writes go through this client only |
| One-shot Script | provider adapter `executeScript` | Fastify → sandbox | one TypeScript module payload per execution; no warm daemon model |
| `ExecutionResult` | provider adapter return value | sandbox → Fastify | structured side-effect contract covering history, outputs, side-work, checkpoint candidates, source usage, archive entries |

## Surface Ownership

Concerns map to a single owning surface. Where a concern appears on more than one surface, the owning surface holds canonical authority and the others consume or render from it.

| Concern | Owning Surface |
|-|-|
| Auth | Fastify control plane (WorkOS server SDK) |
| Orchestration | Fastify control plane |
| Durable state | Convex (durable stores) |
| Canonical code | GitHub (durable stores) |
| Working filesystem | Sandbox runtime |
| Artifact rendering | Fastify control plane (markdown-it + isomorphic-dompurify), with browser-side Mermaid hydration on the client |
| Package export | Fastify control plane (`@liminal-build/markdown-package`) |
| Integration boundaries | Fastify control plane |
| Error taxonomy | Fastify control plane (`server/errors/`) |
| Environment lifecycle | Fastify control plane (durable in `processEnvironmentStates`) |
| Source hydration | Fastify control plane (Octokit + provider adapters) |
| Archive write path | Fastify control plane (Convex archive tables) |
| Review eligibility computation | Fastify control plane (process refs + pinned package context) |
| Live-update fan-out | Fastify control plane (WebSocket upserts) |

## What Design Pages Inherit

Design pages should treat the runtime, framework, data layer, auth provider, sandbox provider set, and rendering pipeline above as fixed; these choices are not re-litigated at design time. Epic-scoped libraries — parsers, adapters, connectors — may be added inside the surface boundaries above without rewiring the stack, but introducing a new runtime, framework, durable store, or provider class should surface as an explicit deviation rather than a quiet addition. Platform-wide invariants that pair with these stack choices live on [Cross-Cutting Decisions](./cross-cutting-decisions.md).
